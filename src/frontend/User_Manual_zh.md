## 1. 简介

**NoteConnection** 是一个强大的知识图谱可视化工具，能将您的 Markdown 笔记转换为交互式分层网络。通过分析笔记之间的关系，它可以帮助您：

- **发现连接** - 找到您不知道存在的概念之间的联系
- **识别学习路径** - 通过理解前置关系来规划学习顺序
- **查找知识聚类** - 查看主题分组
- **高效导航** - 支持大型笔记集合（10k+ 文件）

### 主要优势

- **离线优先**: 构建后完全离线工作
- **GPU 加速**: 可选的 AMD GPU 支持，适用于大规模图谱
- **多语言**: 完整支持英语和中文
- **跨平台**: Windows、macOS 和 Linux 支持

## 2. 快速开始

### 2.1 首次启动

首次打开 NoteConnection 时：

1. **语言选择** 会自动出现
   - 选择 **English** 或 **中文**
   - 您的选择会被保存，稍后可在设置中更改

2. **知识库设置**
   - 点击 **文件** → **更改知识库**
   - 选择包含您的 Markdown 文件的文件夹
   - 这将成为您的活动知识库

3. **加载您的第一个图谱**
   - 使用左上角的下拉菜单
   - 选择 **"所有文件夹"** 以分析所有内容
   - 点击 **"加载"** 按钮
   - 等待分析完成（大数据集会显示进度）

### 2.2 交互式教程

对于新用户，我们建议运行 **交互式教程**：

- 通过 **帮助** → **启动教程** 访问
- 6 步引导式关键功能介绍
- 可随时跳过或重新启动

## 3. 核心功能

### 3.1 布局模式

#### 力导向布局（默认）

- **最适合:** 查看自然聚类和分组
- **工作原理:** 节点相互推开，边将它们拉在一起
- **使用场景:** 探索整体结构

#### DAG（有向无环图）布局

- **最适合:** 理解学习路径
- **工作原理:** 根据依赖关系分层排列笔记（上 → 下）
- **使用场景:** 查找先决条件和依赖关系

**切换布局:** 使用右侧面板中的"布局"下拉菜单

### 3.2 专注模式

**进入专注模式** - 双击任意节点。

#### 布局方向

- **水平（默认）**: 节点居中，入度在左，出度在右
- **垂直**: 节点居中，入度在下，出度在上

#### 交互控制

- **层级间距滑块**: 调整入度/出度层之间的距离
- **节点间距滑块**: 调整同一层节点之间的间距
- **RESET 按钮**: 返回默认间距
- **布局下拉菜单**: 在水平/垂直方向之间切换

#### 阅读内容

- 点击 **"查看具体内容"** 按钮打开完整笔记
- 内容在阅读窗口中打开，包含：
  - Markdown 渲染
  - LaTeX 数学公式支持
  - Mermaid 图表支持
  - 缩放控件（A+ / A-）
  - 全屏模式

#### 退出专注模式

- 点击 **"退出专注模式"** 按钮
- 或双击背景

**专业提示:** 进入专注模式前启用"冻结布局"，可手动定位节点而不会移动。

### 3.3 节点检查

#### 悬停（桌面版）

- 将鼠标移至节点上以查看：
  - 节点名称
  - 度数信息（入度/出度/总计）
  - 连接预览

#### 点击（所有平台）

- 点击节点打开 **统计弹窗**
- 弹窗显示：
  - **入度（红色）**: 引用此笔记的其他笔记
  - **出度（蓝色）**: 此笔记引用的其他笔记
- **弹窗控制:**
  - **拖动** 重新定位
  - **+/-** 放大/缩小
  - **⟲** 重置大小
  - **×** 关闭

### 3.4 模拟控制

位于 **右侧面板**：

#### 冻结布局

- **复选框** 或 **❄️ 图标**（快速切换）
- 停止所有节点移动
- 对于大图谱（>3000 节点）必不可少
- 允许手动拖放定位

#### 速度/阻尼滑块

- 控制模拟稳定的速度
- **较低值**（0.85）：节点弹跳更多，需要更长时间才能稳定
- **较高值**（0.99）：节点快速稳定，移动较少

#### 最小度数过滤器

- 隐藏度数低于阈值的节点
- 用于专注于高度连接的概念

#### 显示孤立节点

- 切换零连接节点的可见性
- 在清理知识库时很有帮助

### 3.5 视觉自定义

#### 着色模式

- **按度数**: 暖色 = 较高度数
- **按聚类**: 每个聚类获得唯一颜色

#### 大小模式

- **统一**: 所有节点相同大小
- **按度数**: 较大节点 = 较高度数
- **按中心性**: 较大节点 = 网络中更中心

#### 渲染器

- **SVG**: 更好的质量，>3000 节点时较慢
- **Canvas**: 更好的性能，大图谱自动激活

#### 边透明度

- 调整连接的透明度
- 较低的透明度有助于处理密集图谱

## 4. 设置与自定义

点击右上角的 **⚙️ 齿轮图标** 访问设置。

### 4.1 常规

#### 语言

- **English** 或 **中文**
- 立即更新所有 UI 元素
- 影响：菜单、对话框、教程、文档

### 4.2 物理引擎

微调力模拟：

#### 排斥力强度

- 默认: -300
- 范围: -1000 到 -50
- 较高（接近 0）= 节点更靠近

#### 链接距离

- 默认: 200
- 范围: 20 到 900
- 较高 = 连接节点之间有更多空间

#### 碰撞半径

- 默认: 30
- 范围: 5 到 100
- 防止节点重叠

### 4.3 性能优化

#### 最大工作线程（内存）

- 默认: CPU 核心数 - 1
- 范围: 1 到 128
- **较高** = 构建更快，RAM 使用更多
- **如果** 出现"内存不足"错误，请降低此值

#### 启用 GPU 加速

**功能说明:** 通过 GPU.js 库使用 WebGL 加速相似度计算（余弦相似度）

**兼容硬件:**

- **强烈推荐:** AMD Radeon RX 6000/7000 系列（RDNA 2/3）
- **同样兼容:** NVIDIA GeForce RTX/GTX 系列（需更新驱动）
- **可用于:** Intel Iris Xe、Arc 系列
- **最低要求:** 任何支持 WebGL 2.0 的 GPU
- **注意:** 集成显卡（Intel UHD、AMD Vega）可用但加速效果有限

**软件要求:**

- **驱动程序:** 最新 GPU 驱动（AMD Adrenalin 23.x+、NVIDIA 530+、Intel 31.x+）
- **浏览器:** 基于 Chromium（Electron）、Chrome 100+ 或 Edge 100+
- **WebGL:** 需要 WebGL 2.0 支持（检查：Chrome 中访问 about:gpu）

**启用方法:**

1. 确保 GPU 驱动程序已更新至最新版本
2. 打开设置（⚙️）→ 性能优化
3. 勾选启用 GPU 加速
4. 点击完成并重新加载页面（Ctrl+R）
5. 在控制台检查 GPU.js initialized 消息

**性能影响:**

- **最佳范围:** 2000-10000 节点（2-5 倍加速）
- **不推荐:** <500 节点（初始化开销导致 CPU 更快）
- **收益递减:** >15000 节点（内存带宽限制）

**需要重新加载页面** 以重新初始化 GPU.js 内核

#### 大文件内存节省策略

- **默认:** 开启
- 流式传输文件内容而不是全部加载到 RAM
- 对于 >10,000 文件必不可少
- 将峰值堆使用量减少 60-80%

#### 紧凑模式（隐藏边）

- **启用于:** 具有 >5000 节点的图谱
- 默认不渲染边
- 在大数据集上大幅提升性能
- 可通过按钮强制加载边

#### 静态模式

- 图谱构建后立即停止模拟
- 推荐用于大图谱（>20k 节点）
- 节点完全不会移动

#### GPU 布局优化（Beta）

- **实验性功能**
- 将力计算卸载到 GPU
- **仅有益于** >2000 节点
- 对于 <2000 节点的图谱可能更慢

#### 深度调试模式

- 在构建期间启用详细日志
- 用于故障排除或开发
- 显示每个分析阶段的计时

### 4.4 视觉效果

#### 边透明度

- 默认: 0.6
- 范围: 0.1 到 1.0
- 较低的值有助于处理杂乱的图谱

### 4.5 阅读

#### 打开模式

- **窗口**: 在浮动窗口中打开笔记
- **全屏**: 笔记覆盖整个图谱

## 5. 性能特性

NoteConnection 包含智能自动优化：

### 5.1 Canvas 自动切换

- 当图谱超过 3000 节点时自动切换到 **Canvas 渲染器**
- 保持流畅的 60fps 性能
- 可在设置中手动恢复到 SVG

### 5.2 物理剔除

- 对于具有 >20,000 条边的图谱
- 仅为边的子集计算力
- 防止 UI 冻结
- 所有边仍然可视化渲染

### 5.3 Web Worker 卸载

- 力模拟在单独的线程中运行
- 前端在布局计算期间保持响应
- 通过状态指示器显示进度

### 5.4 内存优化（v0.9.63+）

- Worker 线程接收文件 **路径** 而不是完整内容
- 按需文件读取减少了线程间数据克隆
- 统计矩阵的资源重用
- 在 10k+ 文件数据集上堆使用量减少多达 70%

## 7. 故障排除

### 7.1 图谱无法加载

**症状:** 点击"加载"无反应或显示错误

**解决方案:**

1. 检查您的知识库文件夹是否包含 `.md` 文件
2. 验证文件夹路径是否正确（**文件** → **更改知识库**）
3. 检查控制台错误（F12 → Console 选项卡）
4. 尝试选择特定子文件夹而不是"所有文件夹"

### 7.2 内存不足错误

**症状:** 构建失败并显示"JavaScript heap out of memory"

**解决方案:**

1. **降低设置中的最大工作线程数**（尝试 2-4）
2. **启用"大文件内存节省策略"**
3. **启用"静态模式"**（禁用连续模拟）
4. 构建知识库的较小子集
5. 对于 Electron：使用 `--max-old-space-size=8192` 增加堆

### 7.3 性能慢/卡顿

**症状:** 图谱不流畅或无响应

**解决方案:**

1. **渲染器:** 对大图谱切换到 Canvas
2. **冻结布局:** 启用以停止物理模拟
3. **紧凑模式:** 对于 >5k 节点启用（隐藏边）
4. **最小度数:** 增加过滤器以隐藏低度数节点
5. **边透明度:** 对于密集图谱降低到 0.2-0.4

### 7.4 节点持续移动

**症状:** 无法手动排列节点

**解决方案:**

1. 点击 **❄️ 冻结布局** 按钮
2. 或在右侧面板中启用"冻结布局"复选框
3. 永久性：在设置中启用"静态模式"

### 7.5 语言未更改

**症状:** 更改设置后 UI 仍显示错误的语言

**解决方案:**

1. 确保您在设置模态框中点击了 **"完成"**
2. 尝试重新加载页面（Ctrl/Cmd + R）
3. 在控制台中检查 `localStorage.user_language`
4. 如果使用 Web 版本，清除浏览器缓存

### 7.6 教程无法启动

**症状:** "启动教程"无反应

**解决方案:**

1. 确保图谱已加载（教程需要节点）
2. 检查教程是否已标记为已完成
3. 通过以下方式重置：`localStorage.removeItem('tutorial_completed')`
4. 重新加载页面

## 8. 高级技巧

### 8.1 优化大型知识库

对于 >5000 笔记：

1. 启用 **内存节省模式** + **静态模式**
2. 使用 **Canvas 渲染器**
3. 启用 **紧凑模式**（默认隐藏边）
4. 将 **最大工作线程数** 设置为 4-6（平衡速度与内存）
5. 考虑构建子集并手动组合

### 8.2 查找学习路径

1. 切换到 **DAG 布局**
2. 点击目标概念（例如，"高级主题"）
3. **沿垂直路径向下跟随** 以查看先决条件
4. 进入 **专注模式** 以隔离路径

### 8.3 识别枢纽节点

1. 使用 **大小依据: 度数** 或 **中心性**
2. 按 **总计** 列对分析表排序
3. 枢纽节点 = 最高度数值
4. 按 **聚类** 着色以查看枢纽是否连接聚类

### 8.4 导出子集

1. 打开 **分析 & 导出** 面板
2. 选择过滤策略：
   - **前 X%**: 获取最高度数节点
   - **最小度数 > X**: 获取高于阈值的节点
3. 选择聚类（可选）
4. 导出为：
   - **JSON**: 导入其他工具
   - **ZIP (MD)**: 获取过滤的 Markdown 文件

### 8.5 自定义样式

对于开发者：修改 `styles.css` 以调整：

- 节点颜色（搜索 `fillColor`）
- 边样式（搜索 `.link`）
- 字体大小（搜索 `font-size`）

### 8.6 GPU 加速最佳实践

**启用 GPU 加速的条件:**

- 您有独立显卡（AMD RX 5000+、NVIDIA GTX 1060+、Intel Arc）
- 图谱有 >2000 节点
- 无 GPU 时构建时间 >30 秒
- 您的 GPU 支持 WebGL 2.0（在 chrome://gpu 检查）
- 您正在运行最新的 GPU 驱动程序

**已测试配置:**

- 优秀: AMD RX 7900 XT/XTX、RX 6800/6900 系列（5-8 倍加速）
- 非常好: NVIDIA RTX 3060/3070/4070（3-5 倍加速）
- 良好: AMD RX 5700、NVIDIA GTX 1660/1080 Ti（2-3 倍加速）
- 中等: Intel Arc A750/A770（1.5-2 倍加速）
- 轻微: 集成显卡 - Intel UHD、AMD Vega（<1.5 倍加速）

**禁用 GPU 加速的情况:**

- 图谱有 <1000 节点（初始化开销导致 CPU 更快）
- 您遇到崩溃或冻结（可能是驱动程序问题）
- 构建时间增加（不兼容的 GPU 或过时的驱动程序）
- 您在控制台看到 WebGL 错误（检查 about:gpu）
- 在无头模式或通过 SSH 运行（无 GPU 访问）

**GPU 问题故障排除:**

1. GPU.js not found 错误:
   - 检查 libs/gpu-browser.min.js 是否存在
   - 确保内容安全策略允许脚本执行
   - 重新加载应用程序

2. WebGL not supported 错误:
   - 将 GPU 驱动程序更新到最新版本
   - 在浏览器标志中启用硬件加速
   - 检查 chrome://gpu 以查看驱动程序阻止列表问题

3. 启用 GPU 后构建更慢:
   - 您的 GPU 可能比 CPU 更旧/更慢
   - 尝试使用更大的数据集（>5000 节点）
   - 检查 GPU 内存使用情况（可能达到限制）

4. GPU 加速不工作:
   - 打开开发者工具控制台（F12）
   - 查找 GPU.js initialized 消息
   - 如果缺失，检查 WebGL 2.0 支持
   - 验证设置是否保留（检查 设置 → 性能优化）

- NVIDIA: https://www.nvidia.cn/Download/index.aspx
- Intel: https://www.intel.cn/content/www/cn/zh/download-center/home.html
